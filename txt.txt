Build a console-based Banking and Transaction Management System TWICE, with identical behavior and identical on-screen text: once in Fortran (Fortran 2008, compiled with gfortran) and once in Julia (1.10 or newer). This is a university group project, and every group member must be able to read and explain the code, so prioritize clarity over cleverness. Use plain, well-commented code with no advanced tricks.

PROJECT STRUCTURE

/fortran/bank.f90
/julia/bank.jl
/tests/inputs/ (one plain-text input file per test case, for piping into stdin)
/tests/TEST_CASES.md
/sample_runs/ (actual captured console output from running each test)
README.md (install, compile, and run instructions for Windows, macOS, and Linux)

FUNCTIONAL REQUIREMENTS (both versions)

Account initialization: on start, set the balance to 5000.00 and display it.
Main menu: show it in a loop until the user chooses Exit:
Check Balance
Deposit Money
Withdraw Money
View Transaction History
Exit
Deposit: prompt for an amount, accept only positive numbers, add to the balance, display the new balance, and record the transaction.
Withdraw: prompt for an amount, accept only positive numbers, reject amounts greater than the current balance, deduct valid amounts, display the new balance, and record the transaction.
Transaction history: display every successful deposit and withdrawal in a neatly aligned table with columns No., Type, Amount, Balance After. If there are none yet, show a clear “No transactions yet” message.
Only SUCCESSFUL transactions are recorded. Failed attempts are never recorded.

INPUT VALIDATION AND ERROR HANDLING

Invalid menu choices (out-of-range numbers like 0, 6, or 9, and non-numeric input like “abc” or an empty line) show an error message and redisplay the menu.
Invalid amounts (non-numeric, empty, zero, or negative) show a specific error message and re-prompt for the amount.
Overdraft attempts show an error that includes the current balance, and the transaction is cancelled.
The program must never crash on bad input. In Fortran, read input as a character string first, then convert with read(..., iostat=) and check iostat. In Julia, use readline() with tryparse(Float64, ...).
Handle end-of-input (EOF) gracefully by exiting cleanly, so piped test files do not cause infinite loops or crashes.

CURRENCY DISPLAY

Display money with two decimal places and the plain text prefix “PHP” (for example, PHP 5000.00) in BOTH versions. Do not use the peso symbol, to avoid Windows console encoding problems. Keep the formatting identical between the two versions.

REQUIRED PROGRAMMING CONCEPTS (make each clearly visible and commented)

Variables with explicit, appropriate data types: Fortran uses real(8), integer, character, with implicit none. Julia uses type annotations such as ::Float64 on struct fields and function arguments.
Arithmetic and comparison operators
Conditional statements: if/else and, where natural, select case in Fortran.
Loops: the main menu loop and the input re-prompt loops.
At least these user-defined procedures in each version: show_menu, read_menu_choice, read_amount (validation), deposit, withdraw, show_balance, show_history. In Fortran, use a mix of functions and subroutines inside a module or contains block.
A data structure for transaction records: a record type with fields type, amount, balance_after.
Fortran: a derived type stored in an allocatable array that grows as needed (use move_alloc).
Julia: a struct stored in a Vector{Transaction}, appended with push!.
Concept map: add a short header comment in each file mapping each required concept to where it appears in the code (with procedure names), to help members write their reflections.

TEST CASES

Write at least 7 test cases in /tests/TEST_CASES.md, each with: ID, description, input sequence, expected output, and pass/fail. Include at minimum:

Check initial balance (5000.00)
Valid deposit (for example, 1500)
Valid withdrawal (for example, 2000)
Deposit of zero and a negative amount (both rejected)
Withdrawal exceeding the balance (rejected, balance unchanged)
Non-numeric amount and invalid menu choices (rejected, user re-prompted)
A full session of several deposits and withdrawals followed by View Transaction History, producing the sample transaction history

Create a matching stdin input file for each test in /tests/inputs/.
